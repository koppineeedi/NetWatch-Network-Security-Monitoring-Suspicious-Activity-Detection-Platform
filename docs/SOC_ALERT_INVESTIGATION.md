# NETWATCH — SOC Alert & Investigation Workflow Documentation

## Overview
Phase 5 implements a full defensive Security Operations Center (SOC) analyst workflow in NetWatch. Detections generated by the backend engine are converted into alert triage records, allowing analysts to create formal investigation case files, post persistent analyst notes, inspect evidence telemetry events, generate chronological case timelines, record verdicts, and resolve/close cases with complete audit logging.

## Analyst Workflow & Lifecycle
```
REAL TELEMETRY (LOCAL_NETWORK, LOG_FILE, TEST_LOG)
        ↓
Normalized NetworkEvent Model (SQLite DB)
        ↓
Detection Engine Evaluation (evaluate_event)
        ↓
Alert Generation (Status: NEW)
        ↓
Analyst Triage & Evidence Inspection (GET /api/alerts/{id}/events)
        ↓
Start Incident Investigation (POST /api/investigations -> Alert Status: INVESTIGATING)
        ↓
Analyst Notes & Evidence Review (POST /api/investigations/{id}/notes)
        ↓
Chronological Case Timeline Assembly (GET /api/investigations/{id}/timeline)
        ↓
Verdict Recording (TRUE_POSITIVE, FALSE_POSITIVE, BENIGN, INCONCLUSIVE)
        ↓
Case & Alert Resolution (PATCH /api/investigations/{id} -> Status: RESOLVED / CLOSED)
        ↓
Audit Logging (audit_logs table)
```

## State Transitions & Validation Rules
### Alert Lifecycle States
`NEW` &rarr; `INVESTIGATING` &rarr; `TRUE_POSITIVE` / `FALSE_POSITIVE` &rarr; `RESOLVED` &rarr; `CLOSED`
- **Validation**: Attempting illegal state transitions (e.g. `NEW` &rarr; `CLOSED` directly) is rejected by backend APIs with HTTP 400 validation error.

### Investigation Lifecycle States
`OPEN` &rarr; `IN_PROGRESS` &rarr; `CONTAINED` &rarr; `RESOLVED` &rarr; `CLOSED`

## API Endpoints
- `GET /api/alerts`: Filterable list (`status`, `severity`, `source_ip`, `rule_code`) with pagination.
- `GET /api/alerts/{alert_id}`: Single alert details with detection explanation.
- `PATCH /api/alerts/{alert_id}`: Controlled status update, analyst assignment, or resolution.
- `GET /api/alerts/{alert_id}/events`: Associated `NetworkEvent` evidence records.
- `GET /api/investigations`: Paginated list of incident investigation case files.
- `POST /api/investigations`: Opens a case from an alert (updates alert to `INVESTIGATING`).
- `PATCH /api/investigations/{id}`: Sets status, verdict (`TRUE_POSITIVE`, `FALSE_POSITIVE`, `BENIGN`, `INCONCLUSIVE`), and resolution summary.
- `POST /api/investigations/{id}/notes`: Adds persistent analyst note.
- `GET /api/investigations/{id}/timeline`: Assembles chronological case timeline.
- `GET /api/ip/{ip}`: Summarizes real DB events, alerts, and detections for a host IP.
- `GET /api/audit`: Returns audit log entries of state changes and actions.
