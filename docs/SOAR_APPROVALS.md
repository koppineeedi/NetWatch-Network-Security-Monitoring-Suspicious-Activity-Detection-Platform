# Approval Workflow & Authorization

## Approval Policies

- `AUTOMATIC`: Action executes without requiring manual approval (used only for non-destructive actions like `NOTIFY_ANALYST`).
- `ANALYST_APPROVAL`: Requires approval by a user with `ANALYST` or `ADMIN` role.
- `ADMIN_APPROVAL`: Requires approval by a user with `ADMIN` role.
- `MANUAL_ONLY`: Action must be requested and approved manually.

---

## Authorization Workflow

1. Action request generated by trigger or playbook step.
2. Approval record created in `soar_approvals` with status `PENDING`.
3. WebSocket event `ACTION_APPROVAL_REQUIRED` broadcast to connected SOC clients.
4. Authorized analyst/admin decides (`APPROVED` or `DENIED`).
5. Upon approval, action is executed automatically by `ActionExecutor`.
